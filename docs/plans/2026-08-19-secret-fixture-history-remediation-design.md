# 测试密钥夹具与 Git 历史清理设计

## 背景

GitGuardian 在 PR 历史中发现了一个 Bearer Token 形状的测试夹具。它只用于验证 DSH Guard 的参数脱敏，目标地址为 `example.com`，不是真实凭据，因此不需要撤销或轮换。但扫描器检查整个 PR 提交历史，仅在最新提交删除字面量不能消除历史告警。

## 方案选择

有三种处理方式：将 finding 标为误报、保留 34 个提交并逐个重写、或把已验证的分支快照压成一个干净提交。选择第三种。误报标记会保留容易反复触发扫描的夹具；逐提交重放的冲突面更大；单提交重建最容易审计，也适合尚未合并、没有下游依赖的本地 Alpha 分支。

## 数据与代码约束

- 测试仍在运行时构造具有代表性的敏感值，继续覆盖 Bearer、GitHub 风格令牌、参数摘要和日志脱敏。
- 仓库文本中不保存完整的密钥形状字面量；需要特定形状时，通过多个无害片段在测试运行时拼接。
- Authorization、Cookie 和 Basic credential 夹具同样在运行时组装，避免完整凭据形状出现在提交文本中。
- 文档只使用环境变量或明显占位符，不提供可被识别为凭据的完整示例。
- 不修改生产策略、匹配规则或脱敏行为。
- macOS sandbox 计划单测显式传入 `platform: 'darwin'`，保证 Linux CI 验证同一编译逻辑；另保留 `platform: 'linux'` 的 fail-closed 用例。

## 历史重写安全措施

重写前创建仅本地备份分支，避免把旧夹具保留在新的远端引用中。新提交从 `origin/main` 的精确基线生成，并在推送前重新扫描提交差异。远端更新必须使用 `--force-with-lease`，只在远端仍指向重写前 SHA 时生效，防止覆盖并发提交。

## 验证标准

- 仓库和 `origin/main..HEAD` 的新增内容不含完整 token-shaped fixture。
- `pnpm check` 通过。
- DSH `0.1.0-rc.7` 完整 E2E 通过。
- macOS sandbox 边界探针通过。
- 新分支相对 `origin/main` 只有一个提交，PR 文件内容与重写前功能快照一致，仅包含明确的夹具清理差异。
