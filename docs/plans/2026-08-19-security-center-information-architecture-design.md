# Security Center 信息架构优化设计

## 目标

让第一次打开“插件安全”页面的用户在十秒内回答三个问题：当前是否安全、插件保护是否工作、Agent 操作保护是否开启。页面继续保持 Companion 只读展示和有限运行时控制的边界，不新增审批、安装、修复或信任捷径。

## 信息架构

页面由一个总览和三个编号分区组成。

总览只显示当前结论、profile、启动方式、Agent 保护状态和最近验证时间。Host 返回的 generation 等技术细节不再占据主视觉，只在“告警与核验”的技术状态中保留。

`01 插件防护` 是产品主能力，标记为“始终开启”。它把原本分散的启动保护、受控插件和报告统计合并到同一语义容器：安装前检查、受控版本、启动前验证。报告计数改为“累计扫描 / 需人工判断 / 已阻止”，并明确这是历史扫描结果，不是当前待办。

`02 Agent 操作保护` 是独立的可选能力。开关保留在分区标题右侧；状态说明只回答“现在会不会检查 Agent 工具调用”和“它不会影响什么”。动作事件与临时授权作为高级记录折叠展示，避免历史数据压过当前状态。关闭确认、运行时持久化、错误处理和降级语义保持不变。

`03 告警与核验` 汇总插件高危事件、权威 CLI 命令和原始技术状态。没有告警时显示短结论；有告警时保持证据、时间和 Sidecar 分析入口。CLI 仍是扫描、审批、安装和修复的唯一权威边界。

## 视觉方向

采用“工业化安全控制台”而不是通用数据看板。每个分区有编号、短描述和左侧状态轨道；绿色表示插件信任链正常，蓝色表示可选 Agent 控制，橙红色只用于需要注意的状态。减少同质卡片和大数字，使用紧凑事实行、细边框和明确留白建立层级。继续继承 DSH 的明暗主题变量，不加载外部字体或图像。

## 交互与可访问性

开关继续使用 `role="switch"`、明确的开启/关闭文本、键盘焦点样式和处理中状态。动作记录与授权使用原生 `details/summary` 折叠，键盘可达；有 Agent 高危告警或状态降级时默认展开。移动端将插件事实卡和告警/核验双栏降为单栏。减少动画，仅对状态轨道和折叠箭头使用短过渡，并尊重 `prefers-reduced-motion`。

## 验收

1. 首屏同时看到总状态、插件防护和 Agent 开关。
2. “插件防护始终开启”和“Agent 防护可选”在视觉和文案上不混淆。
3. 历史 `review` 报告不再被描述为待处理任务。
4. 原有开关、告警、详情分析、复制命令、事件筛选和撤销授权仍可用。
5. 明暗主题、窄屏、键盘焦点和 reduced motion 均保持可用。
