# DSH Guard v0.3 本地 Alpha 运行手册

> 状态：本地 alpha
> 版本：`0.3.0-alpha.0`
> 日期：2026-08-19
> 适用范围：单个开发者、本机 DSH `0.1.0-rc.6`、macOS、Node `22.22+`
>
> 当前产品边界已调整为插件优先，Agent 操作保护默认关闭；本文保留当时的 v0.3 验证记录。

## 1. 这一版解决什么

v0.3 在原有两道门之外补齐插件管理闭环：

1. Trust Gate 在安装或更新前检查明确制品并绑定审批。
2. 可选 Agent 操作保护在显式启用后，对所有 Agent 的正规工具调用执行允许、询问或阻止。
3. Plugin Lifecycle 记录当前有哪些插件受管，并为每次变更保存可验证 generation。

它现在可以安全更新、卸载、修复和回滚，但仍不是 OS 沙箱。已经进入 Host 进程的恶意插件可以直接使用 Node.js API 绕过 Tool Registry。

## 2. 建立和验证开发环境

```bash
git clone git@github.com:Vincentkovsky/dsh-guard.git
cd dsh-guard
corepack enable
pnpm install --ignore-scripts
pnpm check
pnpm --filter dsh-guard link --global
```

准备精确 DSH rc.6 后运行：

```bash
export DSH_BIN=/absolute/path/to/@deepseek-ai/dsh/lib/bin.js
export DSH_NODE=/absolute/path/to/node-22.22-or-newer
dsh-guard doctor
DSH_BIN="$DSH_BIN" DSH_NODE="$DSH_NODE" pnpm test:e2e
```

成功 E2E 除原有 Host API 与 Action Gate 字段外，必须包含：

```json
{
  "lifecycle": {
    "listed": true,
    "multiplePlugins": true,
    "driftDetected": true,
    "repaired": true,
    "updatedTo": "0.3.1-e2e",
    "uninstalled": true,
    "rolledBackTo": "0.3.0-alpha.0"
  }
}
```

E2E 使用随机 sibling DSH home、随机 Guard state 和两个临时插件目录；清理前验证路径前缀，不修改真实 profile。

## 3. 首次安装

```bash
dsh-guard scan /absolute/path/to/plugin --profile web
dsh-guard report <report-id>
dsh-guard approve <report-id>
# 完全退出 DSH GUI
dsh-guard install <report-id>
dsh-guard verify --profile web
dsh-guard plugins list --profile web
```

第一次安装成功会生成 `install` generation。以后对同一个 package 再运行 `install` 会失败，避免把更新伪装成首次安装。

## 4. 查看 inventory 和 history

```bash
dsh-guard plugins list
dsh-guard plugins list --profile web --json
dsh-guard plugins history --profile web
dsh-guard plugins history --profile web --json
```

`list` 会显示 profile、current generation、状态和全部受管插件。非 `verified` 状态返回退出码 2。`history` 中 `*` 表示 current generation；rollback 需要这里的精确 ID。

旧版 `installs/<profile>.json` 只有在真实 profile 仍与旧指纹完全一致时才导入为 `legacy-import` generation。已漂移的旧状态不会被当成新基线。

## 5. 更新插件

update 不联网查询“最新版”，也不自动选择 tag：

```bash
dsh-guard scan some-plugin@2.0.0 --profile web
dsh-guard report <report-id>
dsh-guard approve <report-id>
# 完全退出 DSH GUI
dsh-guard plugins update <report-id>
dsh-guard verify --profile web
```

报告必须对应已受管 package，且版本或 artifact digest 必须变化。真实 add 后的 lock hash、profile fingerprint、bundle 顺序和组合配置 hash 必须与 scan 时的隔离 proposal 一致。

## 6. 卸载插件

```bash
# 完全退出 DSH GUI
dsh-guard plugins uninstall some-plugin \
  --profile web \
  --confirm some-plugin
```

`--confirm` 必须精确重复 package 名。Guard 先在隔离 profile 运行 DSH rc.6 remove，再执行真实 remove。卸载一个插件不会从 inventory 删除其他插件。操作前备份路径和新 generation 会打印在终端。

## 7. 修复漂移

先确认漂移：

```bash
dsh-guard verify --profile web
dsh-guard plugins history --profile web
```

随后完全退出 DSH GUI：

```bash
dsh-guard plugins repair --profile web --confirm web
dsh-guard verify --profile web
```

repair 只恢复 current generation，不猜测目标。它会覆盖五个 profile 控制文件，因此要求精确确认；当前已经一致时返回 no-op。插件运行数据和 workspace 不在恢复范围内。

## 8. 回滚 generation

```bash
dsh-guard plugins history --profile web
# 完全退出 DSH GUI
dsh-guard plugins rollback \
  --profile web \
  --to <generation-id> \
  --confirm <generation-id>
```

rollback 恢复目标 generation 当时的完整插件集合和控制文件，然后创建一个新的 `rollback` generation。它不会移动或删除旧历史。

当前 profile 已漂移时默认拒绝。只有人工审阅漂移内容并接受操作前备份后，才增加：

```bash
--allow-drift
```

## 9. 状态、备份和失败语义

```text
~/.dsh-guard/
├── managed-profiles/<profile>.json
├── generations/<profile>/<generation-id>/
├── backups/<profile>-lifecycle_.../
├── cache/pnpm-store/
└── locks/profile-<profile>.lock
```

状态目录和 generation 目录为 `0700`，文件为 `0600`。generation manifest 校验控制文件 digest；symlink 或损坏状态失败关闭。`doctor` 会检查 lifecycle schema、所有 snapshot 和遗留 lock。

真实操作失败后会恢复操作前控制文件并执行 offline frozen hydration。恢复成功记录 `*-failed-recovered`；恢复无法证明时返回退出码 5、记录 `needs-repair` 并保留备份。不要手工删除未知 lock，也不要在没有审阅路径的情况下递归删除 backups。

## 10. 已知限制

- 只验证 DSH `0.1.0-rc.6`、Node `22.22+`、Apple Silicon macOS；Windows、Linux、Intel Mac 未验证。
- generation 只覆盖五个 profile 控制文件，不备份插件数据库、缓存、运行数据或用户 workspace。
- repair/rollback 依赖本地 artifact 和 pnpm store；cache 缺失时失败关闭。
- 本地状态对同一 OS 用户是 tamper-evident，不是 tamper-proof。
- Action Gate 仍只覆盖 DSH Tool Registry；直接 Node.js `fs`、`fetch`、`child_process` 可以绕过。
- 传递依赖没有全部执行与根包相同深度的 AST 扫描。
- 没有自动更新、private registry、企业签名、团队 RBAC、SIEM 或 OS 沙箱。

## 11. 2026-08-19 Alpha 证据

- `pnpm check`：Core 61、CLI 35、Companion 19，共 115 个测试通过，typecheck 和 build 通过。
- 精确 DSH `0.1.0-rc.6` + Node `22.23.1` E2E：两个受管插件、Host API、Action Gate、漂移、repair、显式 update、uninstall 保留另一插件、rollback 恢复旧版本全部通过。
