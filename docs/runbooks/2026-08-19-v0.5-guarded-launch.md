# DSH Guard v0.5 Guarded Launch 本地运行手册

> 版本：`0.5.0-alpha.1`
> 平台：macOS
> DSH：`0.1.0-rc.7`
> Node：`22.22+`

## 目的

Guarded Launch 把插件信任检查放在 DSH 进程创建之前。它只启动精确匹配当前受管 generation 的 profile；未审批 bundle、控制文件漂移、损坏的生命周期状态和启动参数覆盖都会失败关闭。

它不是 OS sandbox。通过 Guard 审批的插件仍与 DSH 共享正常宿主权限，主 Agent、sessions、settings 和模型凭据保持可用。

## 安装与检查

```bash
cd /Users/vincentjin/CodingProject/dsh-guard
pnpm install --ignore-scripts
pnpm check
cd packages/cli
npm link
cd ../..
dsh-guard doctor
dsh-guard verify --profile web
```

## 受保护启动

```bash
dsh-guard start --profile web -- --host 127.0.0.1 --port 8080
```

DSH 参数必须放在 `--` 后。允许普通应用参数；拒绝 `--profile`、`--patch` 和 loader `--config` 覆盖。退出 DSH 时，Guard 会传递 SIGINT/SIGTERM，并保留子进程退出码。

在 Settings → Plugins → 插件安全中应看到“受保护启动”。若使用原始 `dsh web`，页面会显示“未受保护启动”；这条提示不是事后隔离，原始命令属于显式绕过入口。

## 漂移演练

先关闭 DSH，再在测试 profile 的 `cordis.patch.yml` 中加入一个未纳管 bundle，随后执行：

```bash
dsh-guard start --profile <test-profile> -- --dump-config
```

预期结果：退出码 `2`，输出“DSH 启动已隔离”，并且 DSH 子进程没有创建。检查证据：

```bash
dsh-guard verify --profile <test-profile>
dsh-guard plugins list --profile <test-profile>
```

恢复时不要直接删除证据。对于已审阅的意外漂移，使用精确确认：

```bash
dsh-guard plugins repair --profile <test-profile> --confirm <test-profile>
```

对于有意新增的插件，重新走 `scan → approve → install`。

## 安全限制

- npm 包无法禁止用户直接执行原始 `dsh`；只有 `dsh-guard start` 是受保护入口。
- 双重 fingerprint 校验缩小但不能消灭 spawn 后的本地竞态。
- Guarded Launch 不限制已批准插件的文件、网络或子进程能力；需要整进程限制时使用实验性的 `sandbox run`。
